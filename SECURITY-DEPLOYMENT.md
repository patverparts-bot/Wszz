# ZZWS: запуск защищённой версии

Это подготовленная серверная версия. Локальные изменения не закрывают файлы в существующем публичном GitHub-репозитории. Публиковать новые учётные записи и прайсы туда нельзя.

## Архитектура

Flask + Waitress обслуживают интерфейс, API и кабинет на одном HTTPS-домене. SQLite хранит пользователей, scrypt-хеши, отзываемые сессии (8 часов), подготовленные и опубликованные версии прайса и журнал. В браузер передаются только разрешённые поля каталога. Исходные XLSX не сохраняются после импорта. Сессии представлены случайными токенами; в базе хранятся их SHA-256-хеши. Запросы изменения требуют точного Origin и специального заголовка; CORS выключен.

## Запуск на Render

1. Создать аккаунт Render и подключить отдельный приватный репозиторий с проверенной серверной версией. Не переносить туда старые Excel, архивы и рабочие каталоги. Код можно хранить и публично, если в нём нет данных и секретов.
2. Создать Blueprint из `render.yaml`. Он предусматривает платный Web Service Starter и постоянный диск 1 GB. До подтверждения проверьте текущую стоимость: https://render.com/pricing .
3. Установить `ZZWS_ORIGIN` в точный адрес сервиса, например `https://ИМЯ.onrender.com`, без пути. При смене домена изменить это значение. `ZZWS_DATA_DIR=/var/data` указывает на постоянный диск. Не использовать файловую систему без постоянного диска.
4. После запуска открыть Shell сервиса и выполнить `python -m flask --app server.app:create_app create-admin`. Команда интерактивно запрашивает логин и новый пароль, не выводя пароль. Старые публичные пароли не переносить.
5. Открыть `/admin`, войти, загрузить `PriceList_3.xlsx`, проверить результат и опубликовать. Названия текущих колонок поддержаны, включая «Номенклатура». Формулы нужно предварительно заменить значениями. Неизвестные колонки не передаются клиентам.
6. Добавить клиентов и выдать новые уникальные пароли длиной минимум 12 символов отдельным каналом. Для KP явно указать бренды либо разрешить все; исключения Miele и Sony TV продолжают действовать. Сохранение пользователя отзывает все его сессии. Сброс пароля пока выполняет администратор; самостоятельного восстановления по email нет.
7. Проверить вход Dealers/KP, экспорт, запрет административного API клиенту и отзыв доступа.
8. Перед переключением сохранить закрытую резервную копию данных и прежней версии сайта. Затем закрыть публичный доступ к `pass.xlsx` и прайсам, включая историю, старые публикации и копии. Старые хеши считать раскрытыми. Переход репозитория в private сам по себе не гарантирует закрытия уже опубликованного сайта.
9. После проверки переключить пользователей на новый HTTPS-адрес. На GitHub Pages можно оставить только страницу-переадресацию. Это меняет адрес в браузере. Сохранить `github.io` как домен серверного приложения нельзя; для постоянного собственного адреса нужен свой домен.

## Резервные копии

Постоянный диск нужен для сохранения данных при перезапуске. История версий — не замена резервным копиям. Настройте ежедневный закрытый бэкап `zzws.sqlite` через SQLite backup API и проверьте восстановление. Копию нельзя помещать в публичный репозиторий. На Render проверьте доступность и сроки хранения снимков диска. Для отдельного ручного бэкапа: `python -m server.backup /var/data/backups`.

## Локальная проверка

Установить Python 3.12 и зависимости: `python -m pip install -r server/requirements.txt`.
Проверки: `python -m unittest server.test_security -v`.
Создание локального администратора: `python -m flask --app server.app:create_app create-admin`.
Запуск: `python -m server.run`, адрес `http://127.0.0.1:8080`. Это единственное разрешённое HTTP-исключение; оно предназначено для локальной проверки. Для публикации обязательно установить HTTPS `ZZWS_ORIGIN` и обеспечить TLS на хостинге.

## Ограничения первой версии

- Один серверный экземпляр с SQLite и постоянным диском. Для нескольких экземпляров нужны общая база и распределённые ограничения запросов.
- Защита от перебора по логину и IP: 10 неудачных попыток за 15 минут. За прокси не доверяем произвольному X-Forwarded-For; без настройки доверенного прокси IP может быть общим. Добавить лимиты на стороне хостинга при нагрузке.
- Каталог целиком в рамках прав клиента доступен этому клиенту; его можно скопировать или сфотографировать. Маркировка экспорта помогает учёту, но не предотвращает пересылку.
- Заказы, корзина, избранное и история остаются локальными, как раньше. Импорт личной резервной копии требует действующей серверной сессии того же клиента и не меняет его роль.
- В кабинете доступны ручное редактирование и массовый импорт XLSX по новому шаблону: login, client, sheet, brands, allBrands, organization, address, contact. Импорт требует предварительной проверки и отдельного применения, сохраняет существующие пароли и статус, не удаляет отсутствующих пользователей, не меняет администраторов. Новые пользователи создаются с выключенным доступом и неизвестным случайным паролем: администратор задаёт новый пароль и включает доступ. Старый `pass.xlsx` не импортируется напрямую, чтобы не восстановить раскрытые учётные данные.
- Внешние CDN-скрипты каталога сохранены. Для дальнейшего усиления рекомендуется разместить проверенные зависимости локально и перейти на строгую CSP без inline-обработчиков.
- Перед рабочим запуском необходимы проверка развёрнутой HTTPS-версии, бэкапов и ограничений доступа. Локальные тесты не заменяют эту проверку.
