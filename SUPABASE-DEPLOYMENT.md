# ZZWS: GitHub Pages + Supabase Free

Защищённая версия использует статический интерфейс GitHub Pages и Edge Function `zzws-api` в проекте `zzws-secure`. Собственный Python-сервер, Render и постоянный диск больше не нужны. Внешний вид каталога и правила Dealers/KP сохранены.

## Что уже настроено

- Проект Supabase в организации ZZWS, регион Frankfurt.
- Закрытые таблицы приложения: пользователи, сессии, версии, черновики, журнал. На всех включён RLS; `anon` и `authenticated` не имеют прав чтения или изменения. RPC разрешены только `service_role` и исполняются как invoker.
- Edge Function проверяет права при каждом запросе. Публичный ключ не даёт доступа к исходным таблицам или чужим ценам.
- Supabase Auth проверяет пароли. Для входа используется логин; технические email-алиасы не рассылают письма. Роли и права берутся только из закрытой таблицы, никогда из пользовательских metadata.
- После успешной проверки пароля Auth-сессия закрывается. Приложение выдаёт отдельный случайный токен на 8 часов. В базе хранится его SHA-256-хеш; в браузере — токен в sessionStorage текущей вкладки. Изменение пользователя и блокировка отзывают сессии немедленно.
- CORS разрешает только `https://patverparts-bot.github.io` и локальный предварительный просмотр `http://127.0.0.1:8080`. Другой домен нужно явно добавить в функцию.
- Начальная настройка администратора защищена одноразовым кодом, хеш которого хранится в базе. После создания администратора повторный запуск настройки запрещён.
- Из прежнего файла перенесены только сведения о 31 клиенте (7 KP и 24 Dealers), бренды и контакты. Им назначены логины `client-…`; доступ выключен. Перед включением нужно проверить данные, при желании переименовать логин и задать новый пароль. Старые пароли и их хеши не переносились.
- Прайс проверяется до публикации. Публикация и применение импорта пользователей выполняются транзакционно. Ошибка файла сохраняет действующий прайс.
- Экспорт XLSX формируется сервером из разрешённых данных и содержит получателя и версию. Макросы, формулы и внешние связи в загружаемых XLSX запрещены; текст формул в выгрузках нейтрализуется.
- Обработчик XLSX на сервере — локальная копия SheetJS 0.20.3 с лицензией; браузерная версия также обновлена до 0.20.3 и проверяется SRI.

## Работа администратора

После публикации статической части кабинет будет доступен по адресу `https://patverparts-bot.github.io/ZZWS/admin/`.

1. Войти с новым логином и паролем администратора.
2. Прайс: выбрать `PriceList_3.xlsx`, нажать «Проверить файл», проверить число товаров и примеры, отдельно нажать «Опубликовать». Старую версию можно восстановить из истории.
3. Пользователи: добавить или изменить клиента, назначить Dealers/KP, бренды и дополнительные права. Для нового пароля нужно минимум 12 символов. Передавать его получателю отдельным каналом.
4. Для массового обновления скачать шаблон из кабинета. Колонки: `login`, `client`, `sheet`, `brands`, `allBrands`, `organization`, `address`, `contact`. Логины состоят из латинских букв, цифр, точки, дефиса или подчёркивания. Бренды перечисляются через запятую, `allBrands` — `yes` или `no`.
5. Импорт показывает изменения и требует отдельного применения. Отсутствующие пользователи не удаляются. Существующие пароли, статус и административные права сохраняются. Новые пользователи создаются с выключенным доступом и случайным неизвестным паролем: перед активацией администратор задаёт новый пароль. Старый публичный `pass.xlsx` не используется для проверки входа и не импортирует пароли.

## Проверки и исходники

- SQL-схема: `supabase/schema.sql`. В облаке применены миграции `zzws_private_catalog` и `fix_rpc_variable_names`; последующие изменения следует применять отдельной миграцией через Supabase.
- Функция: `supabase/functions/zzws-api/index.ts`, правила каталога — `catalog.mjs`, закреплённая библиотека и лицензия — в `vendor/`.
- Подключение браузера: `js/api-config.js`, `js/api-client.js`. Здесь допустимы только URL и publishable key; секретных ключей и паролей быть не должно.
- Тесты правил: `node --test supabase/tests/catalog.test.mjs`.
- Перед переключением проверены реальные операции Auth, публикация, фильтрация, экспорт, блокировка, смена пароля, импорт, откат и запрет прямого чтения таблиц.

## Переключение рабочего сайта

1. Просмотреть PR и убедиться, что администратор может войти в предварительный кабинет. Проверить текущий прайс, перенести нужных клиентов и выдать им новые пароли.
2. Согласовать момент перехода: старые пароли и восстановление входа из localStorage больше не действуют. После перехода пользователям потребуется новый логин и пароль.
3. Опубликовать статическую часть через GitHub Pages. Путь `/ZZWS/` поддержан; кабинет использует относительные ссылки.
4. Проверить на рабочем домене вход и запрет доступа без входа, разные группы цен, бренды KP, экспорт и отзыв сессий.
5. Закрыть прежний публичный доступ к Excel: удаление из последнего коммита не удаляет историю, копии и кеши. Требуется отдельно согласованная очистка публичной истории/веток либо перенос чистого интерфейса в новый репозиторий и закрытие старого. Одно слияние PR проблему старых копий не решает. Старые хеши паролей считать раскрытыми.

## Бесплатный план и эксплуатация

Тариф Free ограничен квотами Supabase. При низкой активности проект может быть приостановлен после недели; не следует имитировать активность для обхода правил. Проверяйте текущие ограничения в https://supabase.com/pricing .

Храните закрытые копии исходного прайса и списка клиентов. История версий в той же базе не заменяет независимую резервную копию. На Free нельзя рассчитывать на возможности резервного копирования платного тарифа; восстановление Auth-паролей из пользовательского шаблона не предусмотрено.

Для снижения расхода бесплатного диска удаляйте ненужные старые версии только после сохранения закрытой копии. Приложение не включает автоматические платные ресурсы. Перед подключением платного тарифа или другой организации нужно отдельно проверить стоимость.

Ограничения первой версии: нет самостоятельного сброса пароля по email и MFA; корзина и история заказов остаются локальными. Доступный пользователю каталог можно скопировать или сфотографировать. Уникальные выгрузки и журнал помогают учёту, но не предотвращают пересылку разрешённых данных.

Security Advisor оставляет предупреждение `Leaked Password Protection Disabled`: проверка паролей по HaveIBeenPwned доступна только на Pro и выше. Платный тариф не включался. В приложении проверяется длина новых паролей (минимум 12 символов), действуют ограничение попыток и немедленный отзыв сессий. Подробнее: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection .
